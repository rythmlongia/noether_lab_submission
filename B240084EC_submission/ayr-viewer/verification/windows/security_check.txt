What page code can reach in the real Electron app (Windows 11). Evaluated in the page over the DevTools protocol.
Run on Electron 38.8.6 and repeated on 45.3.2 after the upgrade, with the same results (on 45 the console text reads
"Evaluating a string as JavaScript violates the following Content Security Policy directive ...").

npm audit: Electron 38.8.6 -> high-severity advisories (fixed only in >= 42.11.16; 38 is end of life).
           Electron 45.3.2 -> "found 0 vulnerabilities".

typeof require / process / ipcRenderer / module / Buffer / electron  ->  all "undefined"
Object.keys(window.ayr) -> openCase, confirmCase, rejectCase, getSettings, detectPython, browsePython, browseSolver, runSolver, cancelSolver, onSolverEvent
Object.isFrozen(window.ayr) -> true   (contextBridge freezes the exposed object)
fetch('file:///C:/Windows/win.ini') -> blocked ("Failed to fetch")

CSP test: the page code injects into the DOM
  1. <script>window.__inline=1</script>            -> did NOT run   (violation: script-src-elem, inline)
  2. <img src=x onerror="window.__onerr=1">          -> did NOT run   (violation: script-src-attr, inline)
  3. setTimeout('window.__timer=1')  (string = eval)  -> did NOT run   (violation: script-src, eval;
     console: "Refused to evaluate a string as JavaScript because 'unsafe-eval' is not an allowed source ...")
Every violation was reported twice: once for the <meta> CSP and once for the CSP response header from the app:// handler.

Note: a direct eval('1') sent through Runtime.evaluate (= typed into the DevTools console) DOES run, because
Chromium exempts code entered via DevTools from the page CSP. That is a DevTools privilege, not something page
scripts or injected markup can use (tests 1-3 above).
